End-of-Course Cleanup Guide

CS 55D: Security in Amazon Web Services  ·  Foothill College

This guide walks you through removing all AWS resources created during the course. The goal is to leave your account with no ongoing charges from course work. Follow the steps in order — some resources must be removed before others.

Do this from CloudShell in us-east-1. All course resources were created in us-east-1. Open CloudShell from the AWS console and make sure the region selector shows N. Virginia (us-east-1).

Phase 1 — Audit (see what you have)

Step 1Pull latest scripts and run the audit
cd ~
git -C aws-security-course pull
bash aws-security-course/photoviewer/audit-aws-resources.sh

Read the output carefully. The audit groups resources into three categories:

  • Costs money — NAT Gateway, ALB, VPC Interface Endpoints, EC2, custom WAF Web ACLs, AWS Config, KMS keys, Secrets Manager
  • Free trial (disable after trial ends) — GuardDuty, Security Hub, Macie, Inspector
  • Free / safe to leave — VPC, S3, DynamoDB, CloudFront, Lambda, API Gateway, CloudTrail, Cognito, EventBridge, SNS, CloudWatch alarms, SCPs, Identity Center, IAM roles

Save the output somewhere — you will compare it against a second audit after cleanup.

Phase 2 — Automated cleanup

Step 2Run the cleanup script
bash aws-security-course/photoviewer/week12/week12-cleanup.sh

The script will ask for confirmation, then work through 10 sections in reverse week order. It automatically deletes what it can and flags items that need manual action with a 🔧 icon. The script will not crash if a resource is already gone or cannot be deleted — it skips and continues.

What it does automatically: Detaches and deletes SCPs, deletes EventBridge rules (removes targets first), deletes Week 11 Lambdas (quarantine, image-validator), disables Security Hub (deregisters delegated admin first, then cleans up leftover Config rules), disables GuardDuty and Macie, deletes CloudWatch alarms, deletes Config rules/recorder/delivery channel, disables Inspector, deletes the main Lambda, deletes DynamoDB table, deletes Cognito user pool (domain first), deletes Secrets Manager secrets, deletes course-related SNS topics, schedules KMS keys for deletion (7-day wait), and deletes EventBridge invoke Lambda roles.

What it flags for manual action: CloudFront distribution (must disable before deleting), WAF Web ACL (must disassociate from CloudFront first), VPC and its dependencies, S3 buckets (must empty first), Config S3 bucket, Identity Center users/permission sets, photoviewer IAM roles, and CloudTrail trail.

Phase 3 — Manual cleanup

Work through each 🔧 item the script reported. The order below avoids dependency errors.

Step 3CloudFront and WAF
  1. Go to CloudFront → Distributions. Select the distribution → Disable. Wait for status to change from Deploying to Disabled (~5–15 minutes).
  2. While waiting, go to CloudFront → Security. If WAF protections are shown, click Manage protections → Disable.
  3. Once the distribution is Disabled, select it → Delete.

CreatedByCloudFront-* WAF Web ACLs are managed by the CloudFront Security dashboard and are free. They are automatically removed when you disable CloudFront security protections. You do not need to delete them separately in the WAF console.

Step 4S3 buckets

Three buckets may exist. For each: open the bucket → Empty (confirm) → then go back and Delete (confirm).

  • photoviewer-9876543210 — the Photo Viewer bucket (includes photos/, quarantine/, app/)
  • config-bucket-644094189785 — created by AWS Config for delivery channel
  • aws-cloudtrail-logs-644094189785-* — created by CloudTrail
Step 5VPC

The VPC has dependencies that must be deleted in order:

  1. Delete any NAT Gateways (wait for state: Deleted)
  2. Release any Elastic IPs
  3. Delete subnets (all four — two public, two private)
  4. Detach and delete the Internet Gateway
  5. Delete non-main route tables
  6. Delete non-default security groups
  7. Delete the VPC

The second VPC (vpc-04bca... with no Name tag) is your account's default VPC. Do not delete it.

Step 6IAM roles

For each photoviewer role listed in the audit output:

  1. Go to IAM → Roles → click the role name
  2. Under Permissions, detach or delete all policies
  3. Delete the role

Roles to look for: photoviewer-ec2-role, photoviewer-lambda-role-*, photoviewer-authorizer-role-*, photoviewer-image-validator-role-*, photoviewer-quarantine-role-*. The AWSReservedSSO_* roles are managed by Identity Center — they are deleted automatically when you delete the permission sets or disable Identity Center.

Step 7Identity Center and Organizations (optional)

If you want a fully clean account:

  1. Identity Center → Users — delete Tom and Jerry
  2. Identity Center → Permission sets — unassign from accounts, then delete each set
  3. Organizations → AWS accounts — remove your account from the Production OU (move to Root)
  4. Organizations → Organizational units — delete Production and Staging OUs

Think before deleting the organization. Deleting the organization disables Identity Center and SCPs permanently. If you plan to reuse this account for anything AWS-related, you may want to keep the organization structure.

Step 8CloudTrail

Go to CloudTrail → Trails. Click the trail name → Delete. CloudTrail itself is free, but the S3 bucket it writes to accumulates storage over time (covered in Step 4).

Phase 4 — Verify

Step 9Run the audit again
bash aws-security-course/photoviewer/audit-aws-resources.sh

Compare against your Phase 1 output. Everything that costs money should be gone. The only things that may remain are free-tier resources you chose to keep (Organizations, default VPC).

Step 10Check your bill

Wait 24 hours, then check the billing console:

aws ce get-cost-and-usage \
  --time-period Start=$(date -d '-1 day' +%Y-%m-%d),End=$(date +%Y-%m-%d) \
  --granularity DAILY \
  --metrics BlendedCost

Or go to Billing → Bills in the console to see the current month’s charges by service.

Troubleshooting — lingering services

If the second audit still shows resources that should be gone, use these targeted fixes.

ServiceSymptomFix
Security Hub Still shows Enabled after running cleanup Your account is the delegated admin. Run:
aws securityhub disable-organization-admin-account \
  --admin-account-id YOUR_ACCOUNT_ID \
  --region us-east-1
Then:
aws securityhub disable-security-hub \
  --region us-east-1
Config rules Hundreds of securityhub-* rules still showing as ACTIVE These are created by Security Hub. Disable Security Hub first and wait 10 minutes. If they persist:
aws configservice describe-config-rules \
  --query "ConfigRules[?starts_with(ConfigRuleName,'securityhub-')].ConfigRuleName" \
  --output text | tr '\t' '\n' | \
  while read RULE; do
    aws configservice delete-config-rule \
      --config-rule-name "$RULE"
    echo "Deleted: $RULE"
  done
GuardDuty Still shows a detector after cleanup 
DETECTOR=$(aws guardduty list-detectors \
  --query 'DetectorIds[0]' --output text)
aws guardduty delete-detector \
  --detector-id "$DETECTOR" --region us-east-1
Macie Status shows ENABLED or PAUSED 
aws macie2 disable-macie --region us-east-1
Inspector Status shows ENABLED 
aws inspector2 disable \
  --resource-types LAMBDA --region us-east-1
Config recorder Recorder still active after cleanup Must run in order:
aws configservice stop-configuration-recorder \
  --configuration-recorder-name default
aws configservice delete-configuration-recorder \
  --configuration-recorder-name default
aws configservice delete-delivery-channel \
  --delivery-channel-name default
EventBridge rules Rules still showing after cleanup Must remove targets before deleting the rule:
aws events remove-targets --rule RULE_NAME \
  --ids $(aws events list-targets-by-rule \
  --rule RULE_NAME --query 'Targets[].Id' \
  --output text) --region us-east-1
aws events delete-rule --name RULE_NAME \
  --region us-east-1
KMS keys Keys still showing after cleanup KMS keys cannot be deleted immediately. The cleanup script schedules them for deletion with a 7-day waiting period. They will show as PendingDeletion until then. This is normal — you will not be charged during the waiting period.

Still seeing charges? Go to Billing → Bills → Charges by service to identify exactly which service is generating cost. Then run the audit script again to find the specific resource. If you cannot identify the source, set up a Billing Alarm (you already have one from Week 1) to alert you if charges exceed your threshold.
